01

Malware: the big picture

supportUnit 1.1·8 min·Foundation
+
Why this matters: Everything else depends on distinguishing the entry point, malicious action and persistence.

Start with a mental model

Malware is software designed to perform unwanted or harmful actions. In an exam, explain it using three questions: How does it enter? (infection vector), What does it do? (payload/behavior), and How does it survive or hide? (persistence/evasion).

Delivery→Execution→Payload→Persistence / C&C

Typical actions include stealing credentials, encrypting data, installing a backdoor, monitoring activity, or recruiting the computer into a botnet. C&C means command and control: attacker infrastructure used to send instructions or receive stolen data.

Why reverse engineering is useful

Analysts study a suspicious executable to determine its functionality, indicators of compromise (IOCs), impact and possible detection methods. Software reverse engineering derives understanding from the program rather than building the program from design documents.

✍ Exam writing plan

5-mark template: Define malware (1 point), list 3 behaviors (3 points), state why analysis matters (1 point). Remember: infection vector ≠ payload ≠ persistence.

Common mistake: A program can be malicious without self-replicating. Virus and worm are only two malware categories.
Test yourself before revealing

What is the difference between an infection vector and a payload?

Show answer

The vector is how the code reaches a victim (for example, a malicious attachment); the payload is what it does once executed (for example, credential theft).

📚 Sources: Ch04-Malware, slides 2–8; Practical Malware Analysis (PMA), Chapter 0.

03

Polymorphism, metamorphism and hiding data

coreUnit 1.1·9 min·Compare
+
Why this matters: The poly vs meta distinction is unusually easy to test and easy to confuse.

Two kinds of changing malware

Polymorphic

Changes its encrypted or encoded appearance between copies, commonly by changing encryption keys or the decoding routine while keeping its underlying behavior.

Same payload→Different encrypted bytes

Metamorphic

Rewrites the malware's own code into different but functionally equivalent forms (for example, reordering independent instructions or substituting equivalents).

Same effect→Different instructions

Hiding data and functionality

  • Encoding transforms representation (Base64, XOR) and is not necessarily secret.
  • Encryption hides data using a key; malware may encrypt embedded strings or configuration.
  • Packing compresses/encrypts an executable and restores it at run time; makes static analysis harder.
  • Obfuscation makes code harder to understand without necessarily changing its behavior.
  • Steganography conceals information inside another object, such as image data.

Spot a packed binary: unusually high entropy, very few readable strings, unusual PE section names, or a small import table. These are hints, not proof.

✍ Exam writing plan

Likely question: Differentiate polymorphic and metamorphic malware. Give a definition, what changes, how it frustrates signature scanning, and one contrast. For hiding data, group techniques into encoding, encryption, packing and steganography.

Common mistake: Packing and encryption are not the same as metamorphism; and a high-entropy file is not automatically malicious.
Test yourself before revealing

Does metamorphic malware mainly change encryption keys or its program instructions?

Show answer

Its instructions/code structure. Polymorphic malware is more closely associated with a changing encoded or encrypted representation.

📚 Sources: PMA, Chapters 13, 15 and 18; polymorphic/metamorphic summary is a syllabus-focused synthesis.

Advanced Persistent Threats (APT)

coreUnit 1.1·9 min·Easy 5 marks
+
Why this matters: Your APT slides give a complete question-and-answer pattern: definition → stages → defenses.

An Advanced Persistent Threat (APT) is a prolonged, targeted intrusion where an organized attacker tries to maintain stealthy unauthorized access. Advanced describes resources/techniques; persistent means sustained access; threat refers to the adversary and operation.

1ReconnaissanceIdentify target, people and systems
2Initial compromisePhishing, malware, exploit
3PersistenceBackdoor or other re-entry mechanism
4Privilege escalation & lateral movementExtend access and reach valuable hosts
5ExfiltrationExtract sensitive information
6Cover tracksReduce visible evidence

Detection & mitigation

Detect through EDR, network monitoring, behavior analytics and signatures. Mitigate using patches, MFA, network segmentation, awareness training and incident response. The source slides identify groups such as APT28 and APT29 as examples, with attribution described as alleged.

✍ Exam writing plan

10-mark scaffold: definition (2), four characteristics (2), six attack phases with an example (4), two detection/mitigation methods (2). A neat chain diagram makes this quick to write.

Common mistake: APT is a type of targeted campaign/actor behavior; it is not simply another name for a virus.
Test yourself before revealing

Name the stages immediately after initial compromise in the APT lifecycle.

Show answer

Establish persistence, then escalate privileges / move laterally before exfiltration and covering tracks.

📚 Sources: Advanced Persistent Threats, slides 1–8.

06

Malware-focused network signatures & Snort

coreUnit 1.1·13 min·Very examinable
+
Why this matters: Expect definitions, header/options of a Snort rule, and why content signatures can outlast IP blocks.

A network signature is a recognizable pattern in network traffic that can help detect malicious activity. IOCs include domains, IP addresses, specific HTTP paths, User-Agent strings, packet sizes or unusual recurring requests.

Network controls

  • Firewall/router: filter IPs and ports
  • DNS sinkhole: redirect known malicious domains
  • Proxy: inspect and block web requests

Content-based controls

  • IDS: inspect and alert
  • IPS: may inspect and block
  • Snort: expresses content and header conditions as rules

Read this Snort rule, not memorise every character

alert tcp $HOME_NET any -> $EXTERNAL_NET $HTTP_PORTS (
  msg:"Unusual User-Agent";
  content:"Wefa7e";
  sid:1000001; rev:1;
)

Header: action alert, protocol tcp, source IP/port, direction arrow, destination IP/port. Options: msg alert message, content payload pattern, sid rule ID, rev version. This is a simplified teaching rule based on the distinctive User-Agent in the provided network-signature slides, not a production-ready detection.

Important distinction: IP/domain indicators can change quickly; distinctive protocol fields or byte patterns may remain useful longer. But exact content can also change and cause false negatives. An overly broad signature can cause false positives.
✍ Exam writing plan

10 marks: define signature → network indicators → explain firewall/DNS/IDS/IPS → write a basic Snort rule → label header and options → discuss false positives. Short question: IDS detects/alerts; IPS can prevent/block.

Common mistake: A single suspicious IP or odd User-Agent is evidence to investigate, not proof of malware.
Test yourself before revealing

What is the difference between a Snort rule header and its options?

Show answer

Header specifies action, protocol, endpoints, ports and direction; options contain matching conditions and metadata such as content, message and SID.

📚 Sources: network signature, slides 2–6 and 17–26; PMA, Chapter 14.
07

Covert malware launching

coreUnit 1.1·10 min·Likely long answer
+
Why this matters: Learn four mechanisms at the conceptual level, not undocumented API sequences.

Covert launching means starting malicious code in a way that makes it harder to notice, often by placing execution inside another process. The launcher may unpack or start a payload after initial infection.

TechniqueCore ideaAnalysis clue
DLL injectionCauses a target process to load a malicious DLLUnexpected module within a legitimate process
Direct process injectionPlaces code into another process's address spaceUnusual memory region or thread activity
Process replacement / hollowingReplaces the contents of an apparently legitimate processMismatch between image on disk and memory behavior
Hook injectionUses hooks to execute code in response to eventsUnexpected hook modules / input observation
APC injectionUses an asynchronous procedure call to arrange execution in a threadSuspicious thread / memory context

Why analysts care

The process name can look trusted while its behavior is malicious. Compare process tree, DLL list, memory mappings, threads and network connections rather than trusting a process name alone.

✍ Exam writing plan

10 marks: define covert launching (2), explain DLL injection, process replacement, hook/APC injection (5), why used (1), two investigation clues (2). A table is enough.

Common mistake: A legitimate-looking process name is not evidence that all code running inside it is legitimate.
Test yourself before revealing

What distinguishes process replacement from ordinary DLL injection?

Show answer

Process replacement swaps or remaps the main executable image of a process; DLL injection introduces an additional DLL into the target process.

📚 Sources: PMA, Chapter 12: Covert Malware Launching.
08

Reverse-engineering process: system vs code level

ASKED IN PYQcoreUnit 1.2·12 min·Essential workflow
+
Why this matters: The workflow connects almost every module-1 and module-2 tool question.

Reverse engineering is the process of extracting design or behavior from an existing program or binary. The analysis goal is what it does, how it works, and what evidence it leaves.

1Preserve the sampleRecord metadata, filename, hash, origin
2Static triageStrings, PE headers, sections, imports and AV results
3Observe safelyIsolated sandbox, process/registry/file/network behavior
4Investigate suspicious logicDisassemble, decompile, debug as needed
5ReportPurpose, persistence, IOCs, detection and confidence

System-level reversing

What happens around the program: files, processes, registry, services and network activity. Uses monitoring utilities.

Code-level reversing

What happens inside the program: instructions, calls, branches, algorithms and data structures. Uses disassemblers/debuggers.

Static is inspecting without execution; dynamic is observing during or after execution. Either can be basic or advanced.

✍ Exam writing plan

10 marks: give definition → explain goals → show 5-step methodology → compare system-level and code-level reversing with a tool for each.

Common mistake: A decompiler reconstructs approximate high-level code, not the original source with names/comments intact.
Test yourself before revealing

Why perform static triage before dynamic analysis?

Show answer

It can reveal risks, imports and likely behavior without executing the unknown sample; it helps plan safer, focused dynamic observation.

📚 Sources: intro-binary-reversing, pages 1 and 6; Reverse Engineering, pages 1–7; PMA, Chapters 0–3.
09

Indicators of compromise (IOCs)

supportUnit 1.2·7 min·Quick marks
+
Why this matters: A simple host vs network table often fits a 5-mark question.

An indicator of compromise is observable evidence associated with potentially malicious activity. It supports detection and investigation, but should be interpreted in context.

Host-based IOCs

  • File hash / suspicious filename or path
  • Registry autorun key
  • New service or scheduled task
  • Unexpected process, injected DLL

Network-based IOCs

  • Domain or IP contacted
  • Unusual User-Agent or URI path
  • Periodic beaconing
  • Unexpected destination or data transfer

Hash vs behavior: A file hash precisely identifies the same bytes, but a tiny change creates another hash. Behavior and protocol patterns can generalize better, but risk false alarms.

✍ Exam writing plan

5 marks: definition (1), two host IOCs (2), two network IOCs (2). For extra detail, include one limitation of hash-based detection.

Common mistake: An IOC is not necessarily proof, and a file hash is not a digital signature.
Test yourself before revealing

Give two host IOCs and two network IOCs.

Show answer

Example: suspicious registry Run key and created executable; unusual C&C domain and distinctive HTTP User-Agent.

📚 Sources: PMA, Chapters 1, 3 and 14; network signature slides, pages 7–8.

YARA and STIX: recognize the syntax

coreUnit 1.2·13 min·Syllabus focus
+
Why this matters: YARA is supported by the book; STIX is listed in the syllabus but not developed in the supplied notes.

YARA: a rule for matching file/memory patterns

rule Example_String_Match {
    strings:
        $a = "training.example" ascii nocase
        $b = { 4D 5A }
    condition:
        $a and $b
}

rule name identifies the rule; strings defines text or byte patterns; condition decides when it matches. Here 4D 5A is the MZ marker common in Windows executables. Crucial: this is only an illustrative rule and matches are not necessarily malicious.

YARA helps classify known malware families and search sets of files/memory. Malware may evade brittle signatures by packing or changing its strings.

STIX: structured threat intelligence

STIX = Structured Threat Information Expression. It standardizes a machine-readable way to represent and share threat information. Conceptual objects include Indicator, Malware, Threat Actor and Observed Data, with relationships linking them.

Indicator→indicates→Malware

Example concept: an indicator describing traffic to a suspicious IP may be linked to a malware family. YARA matches local content; STIX communicates structured threat information.

Source gap: STIX terminology is a brief syllabus-aligned bridge. The uploaded PDFs do not provide a full STIX specification or worked STIX document.
✍ Exam writing plan

5 marks on YARA: definition (1), rule parts (3), use/limitation (1). 5 marks on STIX: expansion, purpose, example objects, relationships, advantage for intelligence sharing.

Common mistake: YARA is a rule language for pattern matching; STIX is an information-sharing model. They are not interchangeable.
Test yourself before revealing

What three sections of a basic YARA rule should you recognize?

Show answer

Rule declaration/name, strings section and condition section. An optional meta section may also appear.

📚 Sources: PMA, Appendix B (YARA). STIX explanation supplied as a clearly labeled syllabus bridge.

VirusTotal Intelligence: practical case reasoning

skimUnit 1.2·9 min·Worked example
+
Why this matters: Use this as your case-study answer pattern without needing a live malware sample.

VirusTotal aggregates security-engine detections and contextual information about files, hashes, URLs and domains. In a written case study, explain how to interpret evidence rather than just quote a detection count.

Hypothetical classroom case — not an actual VirusTotal report

Sample: invoice_viewer.exe. Suppose several engines flag it, strings mention a remote address, PE imports hint at network behavior, and sandbox observation shows an added autorun entry.

  1. Compute SHA-256 and record filename/size for reproducibility.
  2. Look up the hash and examine labels, first/last observations and related indicators.
  3. Inspect suspicious strings/imports without execution.
  4. In an isolated lab, verify file, process, registry and network changes.

Show answer

Signatures may be missing, the sample may be new/obfuscated, and automated engines can miss malware; use further static and controlled dynamic analysis.

PYQ Q1 · 10 marks — Define malware and explain any FOUR types with examples

Definition (2 marks)

Malware (malicious software) is software intentionally designed to perform unauthorized or harmful actions such as disrupting operations, stealing information, giving attackers access, or hiding malicious activity.

Any four types (about 2 marks each)

  1. Virus: malicious code that attaches to a host file or program. When the infected item runs, the virus can execute and spread. Example: a virus infecting other executable files when the user runs an infected program.
  2. Worm: self-replicating malware that spreads automatically between vulnerable computers or networks, without needing a user to open each infected copy. Example: a worm scanning networked devices and copying itself to vulnerable hosts.
  3. Trojan horse: a program that appears legitimate or useful but secretly performs an unwanted action; unlike a worm, its defining feature is deception, not autonomous replication. Example: a fake utility that silently installs a keylogger.
  4. Rootkit: software that conceals malware, processes, files or other evidence by manipulating what the system reports. It is often combined with a backdoor. Example: a rootkit hiding a malicious process from standard process listings.
TypeCore word to rememberExam distinction
VirusHost-dependentInfects a host file/program
WormSelf-spreadingReplicates across systems automatically
TrojanDisguisedSeems useful, hides harmful behavior
RootkitConcealmentHides malicious components or activity
2-minute recall: Write the four headings Virus • Worm • Trojan • Rootkit. Under each, write one key characteristic and one example. If you can do that without looking, you've prepared the 10-mark skeleton.

PYQ Q2(a) · 5 marks — Explain reverse engineering and its application areas

Definition (1 mark)

Software reverse engineering is the process of examining an existing program, often without its original source code, to understand its internal structure, functions, behavior, algorithms, or design.

Application areas (any four or five, with a line of explanation)

  1. Malware analysis: determine what a suspicious program does, how it persists and what data it accesses.
  2. Security auditing: find vulnerabilities, suspicious logic or unsafe behavior in compiled binaries.
  3. Interoperability: understand undocumented software interfaces or protocols so independent programs can communicate.
  4. Algorithm and cryptographic research: study algorithms implemented in compiled software.
  5. File-format and network-protocol analysis: discover how files or messages are structured when no specification is available.
  6. Software maintenance and compatibility: investigate legacy binary behavior when documentation or source code is unavailable.
Example: An analyst disassembles a suspicious Windows executable to discover its network communication routine and identify how it contacts an external server.

Sources: intro-binary-reversing.pdf, pages 1–4; Reverse Engineering.pdf, pages 1–3.

Polymorphic vs metamorphic malware and hiding techniques · 10-mark model answer

Introduction: Malware uses obfuscation and code variation to avoid signature-based detection and make reverse engineering difficult.

  1. Polymorphic malware: changes its appearance across copies, commonly by changing an encryption key or decryptor while preserving the underlying malicious functionality. Example: two variants decrypt the same payload but have different byte patterns.
  2. Metamorphic malware: rewrites or rearranges its own instruction sequences while keeping equivalent behaviour; it may substitute equivalent instructions, reorder independent instructions or rename registers.
  3. Difference: polymorphism often changes the encoded appearance and decoder; metamorphism changes the actual code form. Both attempt to defeat exact-byte signatures.
  4. Data hiding: encrypted or encoded strings conceal domains, file paths and configuration from basic strings tools. XOR or Base64-like encodings can hide readable data; encoding by itself is not always encryption.
  5. Packing: stores compressed or encrypted program code with an unpacking stub. The original code appears in memory at runtime, limiting naive static inspection.
  6. Stealth: malware may masquerade as a legitimate file, use persistence and conceal processes or files; behavioural monitoring helps expose activity that byte signatures miss.

Conclusion: analysts combine static inspection, controlled dynamic analysis, memory inspection and behaviour-based indicators to understand changing malware.

Sources: Practical Malware Analysis Chs. 1, 13 and 18; syllabus Unit 1.1. Illustrative examples are explanatory.

Advanced Persistent Threats: phases, detection and prevention · 10-mark model answer

Definition: An Advanced Persistent Threat (APT) is a prolonged, targeted intrusion in which skilled attackers obtain access and attempt to remain undetected for an extended period. APT refers to an attack campaign or actor, not a single malware type.

  1. Reconnaissance: collect information about employees, infrastructure and possible weak points.
  2. Initial compromise: obtain an initial foothold, often through spear phishing or exploitation of a vulnerability.
  3. Persistence: maintain access using backdoors, stolen accounts or scheduled mechanisms.
  4. Privilege escalation: obtain higher privileges to reach more resources.
  5. Lateral movement: move from one host or account to other systems.
  6. Exfiltration: collect and transfer valuable information to an attacker-controlled destination.
  7. Covering tracks: attempt to reduce evidence and avoid detection.

Detection: watch endpoint behaviour with EDR, monitor network connections, analyse anomalies, review authentication events and use known signatures where available.

Mitigation: network segmentation, regular patching, multifactor authentication, employee awareness, least-privilege controls and a tested incident-response plan.

Conclusion: layered controls are required because persistence and stealth make APTs difficult to catch through a single signature.

Source: Advanced Persistent Threats.pdf, pp. 1–8.

Malware-focused network signatures and Snort · 10-mark model answer

Definition: A malware-focused network signature is a pattern in traffic that helps detect communication associated with malicious software, such as a distinctive HTTP header, URI or protocol sequence.

  1. Indicators: domains, IP addresses, DNS requests, unusual HTTP headers and command-and-control traffic can suggest compromise.
  2. Network countermeasures: firewalls filter addresses and ports; DNS sinkholes redirect known bad domains; IDS monitors traffic; IPS can attempt blocking.
  3. Content-based signatures: inspect packet contents rather than relying on IP addresses alone. Distinctive payload patterns can remain useful even when attacker infrastructure changes.
  4. Snort rule structure: a rule has a header (action, protocol, source/destination and ports) and options (message, content and identifiers).
alert tcp $HOME_NET any -> $EXTERNAL_NET $HTTP_PORTS (msg:"Suspicious User-Agent"; content:"Wefa7e"; sid:2000001; rev:1;)

Explanation: alert generates an alert, tcp is the protocol, -> gives traffic direction, content searches for the example string, sid identifies the rule and rev tracks its revision. The sample header string comes from the uploaded network-signatures slides; the compact rule here is illustrative.

Limitations: benign traffic may create false positives; changing, encrypted or unseen traffic can lead to false negatives. Choose distinctive, testable patterns.

Sources: network signature.pdf, pp. 3–4, 17–26; Practical Malware Analysis Ch. 14.

Reverse-engineering process, levels and tools · 10-mark model answer

Definition: Software reverse engineering studies a compiled program to recover its structure, logic and behaviour when source code or design details are unavailable.

  1. Preparation: identify the sample, record hashes, preserve evidence and choose an isolated investigation environment.
  2. Basic static analysis: examine strings, file headers, imports and suspicious resources without executing the file.
  3. Basic dynamic analysis: run only in an isolated lab and observe files, registry, processes and network activity.
  4. System-level reversing: use process and OS monitoring to understand overall program structure, interactions and side effects.
  5. Code-level reversing: use disassembly and debugging to understand individual functions, algorithms, branches and data structures.
  6. Correlation: compare disassembly predictions with observed behaviour and document host/network indicators of compromise.

Tools and purposes: hex editor views raw bytes; disassembler converts machine code into assembly; decompiler approximates higher-level pseudocode; debugger steps execution with breakpoints; system-monitoring tools observe activity. Ghidra supports disassembly and decompilation, while Procmon and Wireshark show file/registry and network events respectively.

Conclusion: static, dynamic, system-level and code-level methods complement one another; no single tool reveals everything.

Sources: intro-binary-reversing.pdf, pp. 5–6; Reverse Engineering.pdf; GHIDRA.pdf; PMA Chs. 1–4.

Covert malware launching mechanisms · 10-mark model answer

Meaning: covert launching means starting or executing malicious functionality in ways intended to blend into legitimate activity, obtain access or hide the responsible program.

  1. Launcher: a small initial program starts another component, separating delivery from the main payload.
  2. DLL injection: makes a process load a DLL that contains additional code, so behaviour appears within the target process.
  3. Direct process injection: places code into another process and causes it to execute there.
  4. Process replacement (hollowing): a legitimate-looking process is started, and its executable content is replaced or redirected to a different image.
  5. Hook injection: event hooks cause a callback to be invoked under selected conditions; malicious programs may misuse them.
  6. APC injection: abuses asynchronous procedure-call mechanisms to arrange execution in a thread under suitable conditions.

Why analysis is difficult: the parent executable may do little work, while the important actions occur inside another process. Analysts correlate process trees, modules, memory and network evidence in a safe lab.

Conclusion: launch methods differ technically but share the goal of disguising or shifting execution; process behaviour is essential evidence.

Source: Practical Malware Analysis Ch. 12; syllabus Unit 1.1.

YARA, STIX, indicators of compromise and VirusTotal · 10-mark model answer

IOC: An indicator of compromise is an observable trace associated with suspicious activity, such as a file hash, path, domain, registry key or network request.

  1. YARA: a rule-based tool for identifying files or memory that match characteristic strings, byte patterns and conditions. Analysts use it to classify suspected malware families.
  2. YARA structure: a rule contains a name, optional metadata, a strings block and a Boolean condition that decides when it matches.
  3. STIX: Structured Threat Information Expression is a structured format for representing and sharing cyber-threat intelligence, including indicators, malware, relationships and attack patterns.
  4. VirusTotal: helps analysts inspect reputation, detection results and related context for a hash or submitted sample. A detection count is evidence, not proof of maliciousness.
  5. How they work together: analysts extract IOCs, use YARA to find related files, share observations in structured STIX data, and consult reputation services for additional context.
